# Launch artifacts

Drafts for the v1.0.0 launch. Each is meant to be copy-pasted with minimal edits.

## Run order

1. **GitHub release** — use [`../RELEASE_NOTES_v1.0.0.md`](../RELEASE_NOTES_v1.0.0.md) as the body for the v1.0.0 tag on GitHub.
2. **LinkedIn** — [`linkedin.md`](linkedin.md) — the resume-signal channel; do this one.
3. **PR to awesome-mcp-servers** — [`awesome-mcp-pr.md`](awesome-mcp-pr.md) — free permanent distribution; takes 10 min.
4. **Tweet thread** — [`twitter.md`](twitter.md) — short-term reach.
5. **Show HN (optional)** — [`show-hn.md`](show-hn.md) — Sunday 8-10am Pacific only.

## After launch

When you're done with this folder, you can either leave it in the repo as a record, or move it to a private gist / `.git/info/` if you don't want launch drafts in the public repo. Most OSS projects leave a `launch/` or `docs/launch/` folder — it signals discipline and helps future you.
